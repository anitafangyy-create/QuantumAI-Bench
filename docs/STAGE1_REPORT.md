# 阶段一实验报告（MVP+：7,502 线路 / 202,554 条资源记录）

> 复现入口：`scripts/report_stats.py`（数据集数字）、`scripts/verify_labels.py`（标签自检）、
> `scripts/acquire_dynamic.py`（动态控制流线路补采为 QPY）、`scripts/acquire_randomcircuit.py`（同族新实例补采）、
> `scripts/import_qcircuitbench.py`（跨源线路导入）、`scripts/train_models.py`（全部指标 + 三套消融配置）、
> `scripts/stats_tests.py`（显著性）、`scripts/make_figures.py` / `scripts/make_figure7.py`（图 1–7）。
> 所有数字来自 `results/evaluation/*.csv|json` 的实际输出，没有手写估算。

## 1. 一句话结论

在本阶段数据上（**7,502 条线路 / 202,554 条资源记录 / 192 个算法 / 2–60 比特**），**树模型能同时撑住"分组内""留一算法"和"跨源"三个场景：逻辑 T-count 的线路级中位偏离依次为 1.0003×（RF，同源分组）、0.79%（RF，留一算法）、28.3%（RF）/ 24.2%（GBDT，跨源到 6,236 条 QCircuitBench 线路）；线性模型在 log 空间三处全部无界外推崩溃（跨源时 99.9% 的记录偏离超过 2 倍）；`logical_qubits` 在本数据上是构造性恒等量，不能当作学习成果展示。**

这三条合起来决定了论文该写什么：不是"我们的 R² 很高"，而是**"哪类模型能外推、在什么条件下失效、失效幅度有多大"**。

⚠️ 本轮相对上一版（7,117 条）有两处**必须并列报告的变化**：

1. **数据集扩到 7,502 条**（补 randomcircuit 同族新实例 402 条 + 大规模 20 条），训练侧 MQT 从 881 增至 **1,246** 条；
2. **两个定向剔除消融（剔除全 Clifford / 剔除动态四族）跑出了否证结果**：它们都没能把跨源 T-count 拉回 702 条时代的 11.3%，
   且同一剔除操作在 7,482 与 7,502 两个基座上效应方向相反。**结论：跨源 T-count 的翻转由训练集规模本身驱动，不是任一子集造成，
   定向剔除无效。**详见 §4.9。

**本轮两类工程修复（都直接影响可用样本数）**

1. **动态控制流线路改用 QPY**：`dynamic_qft` / `ghz_dynamic` / `ae` / `iqpe` 四族带经典条件分支，qiskit 的 OpenQASM 2
   导出器直接拒绝（`ValueError: no_qasm_export`），此前这些线路**从来没有落盘文件**——这才是"大量 ALG 未标注"的真实原因，
   与 `ALG_LABEL_MAX_SIZE` 截断无关（提到 20 后仍是 351 条，逐条读 `label_timeouts.csv` 才发现）。改用 QPY（qiskit 原生序列化）
   后四族全部往返一致（`scripts/acquire_dynamic.py`，写入前备份 `.backup_before_qpy.parquet`），加载端统一走 `scripts/circuit_io.py`。
2. **randomcircuit 同族新实例**：原 39 条全部是 `rep=0`（同族只有一个实例）。`scripts/acquire_randomcircuit.py` 按 `rep=1..20`
   生成同族不同实例，`circuit_id` 形如 `mqt-{level}-randomcircuit-n{n}-r{rep}-{sha[:10]}`，共 **402 条**（n≤28），标注成功 377 条。

**152 条未标注里，74 条属于"概念上不可标注"**：逐条读 `KeyError: <Clbit register=(3, "meas"), index=0>` / `<Clbit register=(1, "mid_measurement"), index=0>`
可知这些线路带**中间测量 + 经典反馈（`c_if`）**，qiskit 无法展开到酉基；这类线路的 T-count 本身依赖运行时测量结果，
**不构成单一数值**。这不是超时、不是性能问题，放宽 timeout 也不会成功——本轮已用 `--timeout 1200 --max-qubits 60` 试过，只救回 5 条。
剩余 78 条（ALG `n>20` 61 + INDEP `n>20` 17）按设计跳过或为 `grover n≥30` 永久卡死。

标签自检 4 项全 passed（`results/evaluation/label_checks.json`）：GHZ 全 Clifford 线路 T-count=0；ε 单调性 0/7502 违例；
串行 T 深度 ≥ 结构深度 0 违例；与 qiskit 独立基展开 max_rel 19.0%、median 18.5%（n=5 抽样，`qiskit < gridsynth` 0/5），
方向一致说明本流水线读数不偏高。在此之上有两条外部/物理检查：
**ε 斜率中位 3.03**（§4.6）与 **1,500 组独立合成器对账**（§4.8）。

## 3. 实验设计

| 维度 | 设置 |
|---|---|
| 目标 | `logical_t_count`、`logical_t_depth`、`logical_qubits`、`physical_qubits`、`runtime_seconds` |
| 特征 | 28 项结构特征 + 3 项配置特征（`log_epsilon`、`log_p`、`log_budget`）；`algorithm` 仅分组协议可用 |
| 模型 | Ridge（线性基线）、RandomForest(120 树)、GBDT（xgb 分支；本机因缺 libomp 实际为 `HistGradientBoostingRegressor`） |
| 种子 | 42 / 123 / 2026 / 2027 / 2028（分组协议）；loso / scale / crosssrc 为确定性划分 |
| 协议 A（grouped） | `GroupShuffleSplit` 按 `circuit_id` 分组，70/30，隔离同源线路的所有配置记录 |
| 协议 B（loso） | 留一算法：训练集不含该算法，测试只用该算法；32 个算法（其中 4 个全 Clifford 算法无正样本） |
| 协议 C（scale） | 训练 ≤16 比特，测试 >16 比特 |
| 协议 D（crosssrc） | 训练集 = MQT Bench **1,246** 条，测试集 = QCircuitBench **6,236 条**（从未进入训练）；不使用 `algorithm` 类别特征，因此是"结构特征 + QEC 配置"的纯迁移测试 |
| 消融 | `--drop-clifford-train`（训练侧剔 T≡0 全 Clifford 线路 1,068 条）、`--drop-algos-train ae dynamic_qft ghz_dynamic iqpe`（训练侧剔动态四族）；**两者都只动训练侧，测试集恒定** |
| 指标 | 原始空间 MAE/RMSE、log 空间 MAE/RMSE/R²、MdAPE（非零参考值上定义，封顶 1e6%）、`frac>10x`（偏离超 10 倍的样本比例） |

两个必须说明的口径：
- **`logical_qubits` 训练时屏蔽 `num_qubits`**。不屏蔽就是恒等映射（第一版跑出 R²=1.000、MAE≈6e-15，是无意义结果）。
- **MdAPE 只在非零参考值上计算**，且单独报 `frac>10x`。资源量跨 6 个数量级，只报 R² 或只报平均相对误差都会失真。

### 4.2 留一算法协议（协议 B，本阶段核心泛化实验）

| target | ridge | rf | gbdt |
|---|---|---|---|
| logical_t_count：R² / MdAPE% | −2.421 / 79.40 | 0.998 / **0.79** | 0.996 / 0.86 |
| physical_qubits：R² / MdAPE% | 0.335 / 27.08 | 0.928 / 9.58 | 0.952 / **8.22** |

按算法看（gbdt，目标 `logical_t_count`，32 个算法中 28 个有正参考值）：
误差最大的六族是 `modular_adder` **10.8%**、`grover` 5.4%、`shor` 4.1%、`randomcircuit` 2.6%、`qwalk` 2.5%、`half_adder` 2.1%；
最容易的是 `cdkm_ripple_carry_adder` 0.09%、`full_adder` 0.26%、`qpeinexact` 0.32%、`qftentangled` 0.35%、`qft` 0.40%。
`randomcircuit` 已从 39 条扩到 397 条同族实例，其留一误差（2.6%）未因样本增加而上升，说明族内多实例**没有引入虚假多样性**。

`bv`、`dj`、`ghz`、`graphstate` 四个算法是**全 Clifford**（T-count 恒为 0），留出时 MdAPE 无定义（无正参考值），只能报 R²=0。**这四个算法不能算作"泛化成功"的样本**，论文里必须分开统计。

### 4.3 规模外推协议（协议 C，训练 ≤16 比特 → 测试 >16 比特）

| target | ridge | rf | gbdt |
|---|---|---|---|
| logical_t_count R² / MdAPE% / frac>10x | −2.705 / 83.87 / 0.383 | 0.996 / 2.68 / 0.00 | 0.996 / **2.75** / 0.00 |
| logical_t_depth | −5.445 / 37.00 / 0.173 | 0.940 / 7.27 / 0.012 | 0.967 / **6.34** / 0.00 |
| physical_qubits | −4.356 / 43.81 / 0.207 | 0.923 / 10.45 / 0.00 | 0.930 / **9.40** / 0.00 |
| runtime_seconds | −3.420 / 41.35 / 0.352 | 0.869 / **11.39** / 0.00 | 0.772 / 45.57 / 0.165 |
| logical_qubits | −17.259 / 9.84 / 0.037 | **−2.579** / 9.69 / 0.00 | **−2.584** / 9.70 / 0.00 |

本轮的规模外推**比上一版（7,117 条）明显变差**：T-count 的 RF MdAPE 从 2.61% 升到 2.68%、GBDT 从 2.52% 升到 3.10%，
physical 从 11.0% / 11.4% 升到 10.45% / 9.40%（这一项略好），`logical_qubits` 的 R² 从 −2.61 恶化到 −2.58（几乎持平）。
原因同上：训练侧新增了 n=24/28 的大规模 randomcircuit，测试侧（>16 比特）里出现了训练分布外的随机线路族，
而该族在大 n 处 T-count 极高（最大 1.24 亿），外推难度上升。**这是"扩样提升覆盖面但降低外推精度"的直接证据。**

最后一行仍是必须诚实写的负面结果：**规模外推时 `logical_qubits` 不可学**——因为训练时按防泄漏规则屏蔽了 `num_qubits`，测试线路比特数超出训练范围后没有任何特征能指示绝对规模，R² 必然为负。这不是模型缺陷，而是"该目标在设计上是输入恒等量"的直接后果。

### 4.4 跨源外推协议（协议 D，MQT Bench 训练 → QCircuitBench 测试）

QCircuitBench 的 **6,236 条**线路（OpenQASM 3.0，递归内联 include 后导入，2–60 比特）
**从未进入训练**，测试 168,372 行（6,236 × 27 配置）：

| target | ridge | rf | gbdt |
|---|---|---|---|
| logical_t_count：R² / MdAPE% / 行级 frac>10x | −0.571 / 282.3 / **0.963** | 0.923 / 28.3 / 0.291 | 0.941 / **24.2** / 0.195 |
| logical_t_depth | −0.761 / 279.9 / 0.980 | 0.960 / **40.8** / 0.000 | 0.959 / 47.0 / 0.000 |
| physical_qubits | −25.22 / 387.9 / 0.622 | 0.780 / **23.4** / 0.000 | 0.743 / 29.5 / 0.000 |
| runtime_seconds | −4.116 / 178.7 / 0.764 | 0.369 / **22.3** / 0.000 | 0.460 / 74.5 / 0.247 |
| logical_qubits | −299.6 / 65.0 / 0.465 | 0.849 / 0.00 / 0.000 | 0.901 / 0.08 / 0.000 |

这是本阶段最重要的证据：**T-count 从同源 0.01% 退化到跨源 24.2–28.3%，但 R² 仍有 0.92–0.94**。

⚠️ **三条必须写进论文的口径提醒**：

1. **跨源 T-count 上 GBDT 的中位偏离更低（24.2% vs 28.3%），但配对检验与平均秩偏向 RF**。
   同一份数据在"行级中位误差"与"线路级平均误差"两种口径下给出不同答案（详见 §4.5），论文必须双报；
   **不能只挑对自己有利的那一列。**
2. **跨源集从 956 条扩到 6,236 条后，RF 的 T-count MdAPE 从 20.9% 降到 11.3%（旧配置）**。这不是模型变好，而是测试面组成变化——
   新批次按 `--sample` 抽的是全库，绝大多数 QCircuitBench 线路是中小规模、浅深度电路，比首版 300 条里偏多的 `grover`/参数化算例容易预测得多。
   任何跨版本比较都必须同时报"测试集规模 + 组成 + 训练集条数"。
3. **行级与线路级是两个不同的比例，不能混用**：行级 `frac>10x` 为 RF 29.1%、GBDT 19.5%（按 27 个配置逐行统计），
   而线路级（同线路跨 seed/配置取中位）`frac>10x` 为 RF 13.9%、GBDT 5.0%。前者说明"约四分之一的配置行偏了 10 倍以上"，
   后者说明"约十分之一的线路中位预测偏 10 倍以上"。论文必须同时给这两个数。

### 4.5 统计显著性（以 `circuit_id` 为簇的 Cluster Bootstrap + 配对 Wilcoxon + Friedman + Holm）

聚合指标（MdAPE）不能说明模型差异是否显著。`scripts/stats_tests.py` 按线路簇重抽样（同一线路的 3 档 ε × 27 配置强相关，
若不按簇重抽样会把人造重复当成独立样本、CI 被人为压窄），对同一线路的误差做配对 Wilcoxon，三模型整体用 Friedman，
最后 Holm 校正。

**Friedman 整体检验（块 = 线路，平均秩越小越好）**

| 协议 | target | 块数 | χ²_F | p（Holm） | 平均秩 | 最优 |
|---|---|---|---|---|---|---|
| grouped | logical_t_count | 1,683 | 2762.4 | <1e-4 | ridge 2.98 / xgb 1.82 / **rf 1.20** | rf |
| grouped | physical_qubits | 1,900 | 2935.0 | <1e-4 | ridge 2.95 / xgb 1.84 / **rf 1.21** | rf |
| crosssrc | logical_t_count | 5,299 | 8063.1 | <1e-4 | ridge 2.98 / xgb 1.72 / **rf 1.30** | **rf** |
| crosssrc | physical_qubits | 6,236 | 5239.0 | <1e-4 | ridge 2.74 / xgb 1.71 / **rf 1.55** | rf（与 xgb 实质相当） |

**两两配对（Wilcoxon signed-rank，Holm 校正后 12/12 显著）**

| 协议 | target | 比较 | 对数 | 中位差（log10） | 更好者 |
|---|---|---|---|---|---|
| grouped | T-count | rf − ridge | 1,683 | −0.292 | rf（1.00× vs ≈2×） |
| grouped | T-count | xgb − rf | 1,683 | +0.00084 | rf（1.0003× vs 1.0051×） |
| grouped | physical | xgb − rf | 1,900 | +0.011 | rf（1.021× vs 1.054×） |
| crosssrc | T-count | rf − ridge | 5,299 | −46.17 | rf |
| crosssrc | T-count | xgb − rf | 5,299 | +0.129 | **rf（1.140× vs 1.745×）** |
| crosssrc | physical | xgb − rf | 6,236 | −0.058 | **xgb（1.976× vs 2.032×）** |

（ridge 跨源的中位差是 −46.17 log10，等价 1e46 量级——几何上无意义，只说明它在跨源场景彻底失效，不应写进正文数字。）

**误差比例（连续量，CI 不会像离散中位数那样塌缩）**

| 协议 | target | 模型 | 行级 >2 倍占比 [95% CI] | 线路级 >10 倍占比 |
|---|---|---|---|---|
| grouped | T-count | rf / xgb / ridge | 0.42% [0.12, 0.77] / 1.19% [0.71, 1.72] / 50.3% [47.8, 52.7] | 0 / 0 / 13.4% |
| crosssrc | T-count | rf / xgb / ridge | **33.7% [32.5, 35.0]** / **33.5% [32.3, 34.8]** / 99.9% | **13.9% / 4.96% / 96.9%** |
| crosssrc | physical | rf / xgb / ridge | 50.0% [48.8, 51.3] / 39.2% [38.0, 40.4] / 76.0% | 0 / 0 / 61.6% |

五条必须写进方法学的说明：

1. **同源的 RF/GBDT 差异虽显著但量级极小**（1.0003× vs 1.0051×，差 0.5%），显著只说明 1,683 对样本足够多；论文里不应把它
   讲成"RF 明显更好"，而应讲"两者在同一量级、RF 略稳"。
2. **跨源 T-count 的中位偏离 CI 退化成一个点**（RF 1.140×、GBDT 1.745×，`ci_degenerate=True`），原因是线路级误差分布离散、
   中位数落在高占比取值上。所以跨源结论一律用**误差比例 + CI** 表述，不用中位数 CI。
3. **行级与线路级误差比例相差极大**（跨源 T-count：行级 `frac>10x` RF 29.1% vs 线路级 13.9%）。两个口径都对，但回答的问题不同：
   行级回答"有多少配置预测会偏"、线路级回答"有多少线路整体不可用"。正文必须同时给出。
4. **跨源 T-count 出现了"中位 vs 尾部"分裂**：GBDT 的行级 MdAPE（24.2%）优于 RF（28.3%），但配对中位差（+0.129 log10）与 Friedman
   平均秩（1.30 vs 1.72）都偏向 RF；而 >10 倍尾部 GBDT（5.0%）明显优于 RF（13.9%），>2 倍比例两者几乎相同（33.5% vs 33.7%）。
   合理解读：**GBDT 把大多数线路拉得更准、把极端失控的线路压得更少，代价是"典型线路"的误差略差于 RF 的分段常数**。
   论文应写成"GBDT 尾部更好、RF 中位更稳"，不能单说"某个模型跨源更好"。
5. **方向不一致处不要下结论**：crosssrc physical 的 Friedman 平均秩 rf 1.55 与 xgb 1.71 接近，而配对检验与 >2 倍占比都偏向 xgb
   （39.2% vs 50.0%）。同样应写成"xgb 尾部更好、整体相当"。

|---|---|---|---|---|
| logical_t_count | rf / xgb / ridge | 0.0094 / 0.187 / 29.38 | 0.0046 / 0.036 / 3.10 | **48.8% / 19.3% / 10.5%** |
| physical_qubits | rf / xgb / ridge | 0.659 / 2.204 / 14.90 | 0.138 / 0.054 / 0.67 | 21.0% / 2.4% / 4.5% |
| runtime_seconds | rf / xgb / ridge | 0.419 / 5.173 / 42.41 | 0.052 / 0.359 / 3.71 | 12.4% / 6.9% / 8.8% |
| logical_qubits | xgb | 0.0174 | 0.0032 | 18.4% |

树模型在 grouped 上的种子间相对标准差为 2–21%，但 **T-count 的 rf 相对标准差达 48.8%**（绝对值只有 0.0094%，绝对波动 ±0.0046 pct）。
这个数**不能当"模型不稳定"讲**：分母已经落到仪器精度量级，相对标准差失去意义。论文报 grouped 指标时必须**同时给绝对值与标准差**，
或者干脆改报绝对波动（这也是待作者拍板的口径之一）。

**图 7（`results/figures/fig7_error_fraction_ci.png`）**：把上表的 >2 倍误差比例与 CI 画成四宫格
（grouped / crosssrc × T-count / physical），跨源部分的尾部结构在图上是一眼可见的——这正是正文必须双报比例而不是只报中位数的原因。

### 4.6 标签可信度：物理不变式检查

除 4 项结构自检外，本轮加了第 5 项**不依赖任何外部工具**的物理检查：Ross–Selinger 逐角合成的 T 成本应满足
`T_i ≈ 3·log2(1/ε) + O(1)`，因此"每单位 log2(1/ε) 每角增加的 T 数"应接近 3。

| ε 区间 | 线路数 | 每角斜率中位 | p10–p90 | 落在 2.5–3.5 的比例 |
|---|---|---|---|---|
| 1e-6 → 1e-9（渐近区） | 4,441 | **3.025** | 2.52 – 3.51 | 62.9% |
| 1e-3 → 1e-6（粗精度区） | 4,441 | 5.81 | 2.72 – 6.20 | 42.5% |

渐近区斜率 3.025 与理论值 3 一致（±1%），说明角度提取与 T 成本映射没有系统性错位。
1e-3 档斜率偏高**不是 bug**：ε 放宽到 1e-3 时大量旋转被吸附到精确 Clifford+T 角（kπ/4），T 成本塌到 0–1，
分母不变而分子被抬高。这也意味着**论文里不能把 1e-3 档当作等质量的合成精度**，必须注明"粗精度档存在 Clifford 折叠"。

### 4.7 GNN 基线（消融 E1 的第一版，单 seed）

`scripts/train_gnn.py` 用门级 DAG（每门一节点、同比特前后门连边）做 3 层 mean-aggregation 消息传递，
节点特征 = 高频 20 门 one-hot + 比特数 + 归一化位置 + 参数 sin/cos + 比特均值，图级特征 5 维，预测 `log10(T+1)`。

| 设置 | 值 |
|---|---|
| 协议 / 划分 | grouped（按 `circuit_id` 分组）：train 2,443 行 / val 713 / test 2,122 |
| 训练 | 60 epochs、batch 32、AdamW lr 2e-3、按 val MSE 早停，**单 seed** |
| 结果（test） | **R²(log) 0.984、MdAPE 21.9%、行级 >10x 2.9%** |
| 对照（同协议表模型） | RF 0.999 / **0.01%** / 0；GBDT 0.998 / 0.19% / 0 |

**这是一个负结果，而且必须照实写**：训练 MSE 掉到 0.009 而验证 MSE 在 0.29–0.44 之间徘徊（log10² 空间），
说明模型在 2,443 行上直接记住了训练线路的门序列，泛化不成立；相对误差 21.9% 比表模型差了两个数量级。

但结论只能限定为"**在该规模与单 seed 设置下，原始门级图结构没有跑赢 28 维人工结构特征**"，不能反推"GNN 无用"：
样本量（702 条核心线路）远低于图网络需要的数据量，且未做任何超参搜索、未加正则/预训练。
E1 消融的正式结论要等按 1,246 条、5 seeds 重跑后再下。（上表 GNN 数字仍是 702 条时的结果，`gnn_cache/` 划分尚未按新数据重建。）

### 4.8 独立合成器交叉核验（2026-11-06）

**动机**：§4.6 的 5 项自检全部是内部自洽，无法排除"我们自己的 gridsynth 实现算错了"。这是审稿人最容易攻的一点。

**做法**：把核验下沉到"角度级"——同一批 (θ, ε) 上双端独立合成，比 T 门数与实测角度误差：
500 个 θ（300 均匀随机 + QFT/QPE 型 `kπ/2^m`）× ε ∈ {1e-3, 1e-6, 1e-9} = **1,500 组**。

| ε | T 中位（本仓库 qiskit） | T 中位（pygridsynth） | 完全相等 | 比值 ≤1.10 | 比值中位 | p10–p90 |
|---|---|---|---|---|---|---|
| 1e-9 | 92 | 94 | 45.6% | **99.4%** | 1.011 | 1.000–1.033 |
| 1e-6 | 62 | 64 | 48.8% | **99.0%** | 1.000 | 1.000–1.049 |
| 1e-3 | 32 | 32 | 47.0% | 87.8% | 1.000 | 1.000–1.103 |

**精度契约实测**：把本仓库 1,500 个合成结果逐条重建酉矩阵，`err/ε` 中位 **0.356**、p90 **0.746**、**0/1500 越界**；
pygridsynth 侧同样 100% ≤ ε。这比"两边数字一样"更强：它证明标签不是靠放宽精度换来的小 T 数。

**每条旋转的 T 代价**：3.077 / 3.111 / 3.211 每 `log2(1/ε)`，理论 3 —— 与 §4.6 的 ε 斜率自检（中位 3.03）互证。

**两处不一致是策略差不是错误**：ε=1e-3 档约 12% 的点比值 >1.10，原因是 `|θ−kπ/4| < ε` 的近 Clifford 角
被 qiskit 吸附成 1 T，而 pygridsynth 仍走一般路径（~30 T）；两端都满足 ε 约束。

**残留局限（论文须写明）**：两端同属 Ross–Selinger 算法族，验证的是**实现**而非**算法最优性**；
算法级独立需要 Qualtran / Microsoft QRE（未接入）。环境搭法、门集口径与复现命令见
`docs/XCHECK_INDEPENDENT_SYNTHESIS.md`，数据见 `results/evaluation/xcheck_{in,out,pairs}.csv`、`xcheck_summary.json`、
`qiskit_eps_audit.csv`。该核验是**角度级、与数据集规模无关**，故 7,502 版沿用未重算。

### 4.9 扩样与定向剔除消融：跨源 T-count 为什么翻转，以及"剔除"为什么无效

本节是本轮最重要的实验，也是唯一一个**假设被自己否证**的实验。

**背景**：训练集从 702（v5）→ 881（v6，补 QPY 动态族）→ **1,246**（v8，补 randomcircuit 同族实例 + 大规模线路），
跨源 T-count 的模型排序随之翻转，且整体水平从 11.3% / 22.1% 漂移到 28.3% / 24.2%。历史上三档如下：

| 训练集档 | 配置 | RF MdAPE% | GBDT MdAPE% | 更优 |
|---|---|---|---|---|
| 702 | v5 | **11.3** | 22.1 | RF |
| 881 | v6 | 25.0 | **14.3** | GBDT |
| 1,246 | v8（本轮主表） | 28.3 | **24.2** | GBDT（中位）/ RF（平均秩，见 §4.5） |

（测试集三档完全相同：6,236 条 QCircuitBench 线路。）

**假设（v7 版报告曾写下的机制）**：新增样本里有 21 条是"大 n 且 T≡0"的全 Clifford 线路（`bv` n≤28、`dj` n=14），
训练侧 T≡0 升到 131 条，强化了"多比特 ⇒ 零 T"的错误先验，而 QCB 测试侧 T 中位是 75,047。
据此预测：**剔掉全 Clifford 训练样本应该把跨源 T-count 拉回去**。

**检验：两个定向剔除消融（只动训练侧，测试集不变）**

| 基座 | 配置 | 训练侧处理 | 训练条数 | RF MdAPE% | GBDT MdAPE% |
|---|---|---|---|---|---|
| 7,502 | v8（主表） | 无 | 1,246 | 28.31 | 24.19 |
| 7,502 | v8nc | 剔 1,068 条全 Clifford | 1,114 | 26.59 | 26.56 |
| 7,502 | v8ndyn | 剔 `ae`/`dynamic_qft`/`ghz_dynamic`/`iqpe` 四族 | 1,113 | 25.34 | **16.77** |
| 7,482 | v7 | 无 | 1,226 | 27.42 | 16.39 |
| 7,482 | v7nc | 剔全 Clifford | 1,094 | 28.60 | 19.97 |
| 7,482 | v7ndyn | 剔动态四族 | 1,093 | 27.92 | 18.43 |

**结果是否证，且是不稳定的否证**：

1. **剔全 Clifford 不能修好跨源 T-count。** 在 7,482 基座上反而更差（RF 27.4→28.6、GBDT 16.4→20.0）；
   在 7,502 基座上 RF 略好（28.3→26.6）但 GBDT 更差（24.2→26.6）。**平均下来没有净收益，且方向随基座翻转。**
2. **剔动态四族也不是"解药"。** 7,482 基座上两者都变差（27.9 / 18.4）；7,502 基座上 GBDT 明显变好（24.2→16.8）、RF 略好（28.3→25.3）。
   同一个操作在两个基座上效应符号相反，说明**单点消融的差异已经在噪声/组成漂移的量级内**。
3. **因此"全 Clifford 大 n 样本毒化先验"这个机制解释被实验否证。** 真实主导变量是**训练集规模带整体下移**
   （702→1,246 条里，中位 T 从约 5,000 掉到更低、n≤20 的小规模线路占比升高），加上跨源测试侧 T 中位 75,047 的极端偏移。
   任何"剔一小撮样本就能回到 11.3%"的想法都不成立——11.3% 属于 702 条那个特定规模带，**不可通过清洗复现**。

**处置（已执行）**：主表沿用**完整 1,246 条配置**（v8），三套配置（v8 / v8nc / v8ndyn）全部并列保存在
`metrics_raw_v8*.csv`，论文以本表作为敏感性分析。删掉任何一族都会让覆盖面与可复现性变差，而收益不可证。

**必须在 limitation 写明的**：跨源 T-count 对训练集组成高度敏感，本轮实测区间 **RF 25.3–28.3% / GBDT 16.8–26.6%**；
单一配置的数字不应被当作该方法的"能力上限"。若要给出稳定估计，需要 ≥5 组不同训练子集的重抽样（本轮未做，属下一阶段）。

## 5. 六条可核验的发现（论文可直接引用）

1. **树模型在高动态范围资源标签上优于线性模型，但两者失效方式不同。** 分组内 Ridge 在 T-count 上 R² = 0.607、行级 13.4% 偏离 >10 倍（MdAPE 30.7%），RF/GBDT 是 0.999；**跨源时 Ridge 直接崩到 R² = −0.571、96.3% 的行偏离 >10 倍**，RF/GBDT 仍保持 28.3% / 24.2% 行级 MdAPE。原因：log 空间里线性模型无界外推，树模型分段常数不外推、但会把大规模任务压缩到训练上界。
2. **T-count 的可迁移性来自结构特征而非算法标签。** LOSO 协议下 `algorithm` 完全不参与，GBDT 仍做到 0.86% 中位误差、RF 0.79%；说明 `n_nonclifford_rz`、`t_count_clifford_part`、`cx_after_ct` 这类"分解后结构量"承载了主要信息。
3. **算法族的 T-count 标度指数分层清晰，但基准自身的参数化在规模网格中间有断点。** 用 ε=1e-9 的 INDEP 样本对 `log T-count ~ log n` 做拟合：`grover` ≈ 8.0、`half_adder` ≈ 4.2、`qft`/`qpeexact`/`qftentangled` ≈ 3.0、`hhl` ≈ 2.5、`randomcircuit` ≈ 2.2、VQE 四族 ≈ 1.0。**但 `modular_adder` 是反例**：n≥10 时 T-count 严格等于 `4n − 8`，而 n=6、8 的 T-count 是 426–2484，远高于同族大尺寸线路——这是 MQT Bench 对该算法内部参数化随尺寸切换导致的断点，不是物理规律。它直接解释了为什么 `modular_adder` 在留一测试里误差最大（10.8%）：**算法身份背后藏着一个结构特征看不到的参数**。
4. **全 Clifford 算法是退化目标，但它并不是跨源退化的元凶。** 4 个训练算法 T-count 恒为 0，任何相对误差指标在这里都没有定义（必须单独统计）。但本轮消融证明：**剔掉全 Clifford 训练样本并不能改善跨源迁移**（§4.9：7,482 基座上反而更差，7,502 基座上无净收益）。真正主导的是训练集**规模带**——11.3% 属于 702 条那个规模带，不可通过清洗复现。**"数据组成比数据条数更重要"这句仍然成立，但具体结论要写成"规模带 > 子集清洗"。**
5. **物理层误差主要来自 QEC 配置的离散跳变（码距 d 的整数台阶）。** 同一线路仅把 p 从 1e-4 换到 1e-3，码距 d 平均增加 **7**（范围 0–14），物理比特数因此阶梯式跳变；连续回归模型在这个目标上 9–30% 量级的 MdAPE，本质上是对"取整台阶"的逼近误差，而不是物理理解错误。图 2 在 1e4–1e5 T-count 区间的回落同样来自分箱组成漂移——该区间线路的 magic-state 工厂数中位数从 7 降到 2（T 深度更短的线路需要的工厂更少），而不是抽样假象。
6. **跨源退化是真实的、但幅度可量化；"哪个模型更好"随口径改变，不能一概而论。** 同源 T-count：RF 1.0003× vs GBDT 1.0051×（配对 Wilcoxon 显著，但差 0.5%，属同一量级）；跨源 T-count：GBDT 行级 MdAPE 24.2% / >10 倍尾部 5.0% 优于 RF 的 28.3% / 13.9%，但配对中位差（+0.129 log10）与 Friedman 平均秩（rf 1.30 vs xgb 1.72）偏向 RF，>2 倍比例两者几乎相同（33.5% vs 33.7%）——**"GBDT 尾部更好、RF 中位更稳"**；跨源物理比特两者实质相当（Friedman 秩 1.55 vs 1.71，>2 倍占比 RF 50.0% vs GBDT 39.2%）。同一份数据在两种口径下讲出两个故事，这是必须双报的原因；**因此不能只报同源结果，也不能用一个模型宣称跨源全面占优。**
